# 失败场景与恢复方式

以下表格描述当前代码的稳定错误边界。错误码是服务端/API 的代码，不代表外部平台具体原因；为避免泄露响应正文、请求头或凭证，线上页面只显示安全提示。

| 场景/输入 | 用户看到 | 内部错误码 | 恢复方式 | 限制 |
| --- | --- | --- | --- | --- |
| 提交目录之外的样例 ID | 提示重新选择固定样例；HTTP 400 | `unknown_scenario` | 从页面的 10 个样例重新选择 | 不接受自由文本或用户自定义资料 |
| Dify 执行超过 30 秒 | AI 分析超时，可安全重试 | `dify_timeout` | 使用同一请求 ID点“重试”，查找既有记录并更新，不新建第二条 | 函数整体处理预算有限；持续超时需运营者检查 Dify |
| Dify 返回缺字段、无效 JSON 或未通过分析约束 | 结果未完成，可安全重试 | `dify_invalid_output` | 运营者检查并修复 Workflow 输出；访客复用原请求 ID | 不合格输出不会写成 `completed` |
| 获取飞书租户访问令牌失败（应用凭证无效、缺失或认证接口不可达） | 演示表暂时无法连接，请稍后重试 | `feishu_auth_failed` | 管理者检查 App ID/Secret 和认证接口状态 | 该码仅表示令牌获取失败；页面不展示上游正文或凭证 |
| 查询请求 ID 对应的多维表格记录失败 | 暂时无法检查本次演示记录，请稍后重试 | `feishu_lookup_failed` | 管理者检查 app/table 标识、记录读取权限和飞书服务状态；修复后可用原请求重试 | 不能把查表错误误判为认证错误 |
| 创建处理中演示记录失败 | 暂时无法保存演示记录，请稍后重试 | `feishu_create_failed` | 管理者检查专用演示表写入权限、字段名与服务状态；复用原请求 ID 重试 | 若上游已写入但响应丢失，重试会先按请求 ID 查找 |
| 分析生成后，更新记录的 HTTP/网络请求失败或飞书业务错误 | 分析结果暂时无法保存，请使用相同样例重试 | `feishu_update_failed` | 管理者检查表访问和字段配置；复用原请求 ID，让服务先读取现有记录再恢复 | 失败响应无法确认写入是否生效；记录可能仍在处理中，也可能已完成 |
| 飞书接口返回不可解析的 JSON、缺少字段或结构不符 | 演示记录服务暂时返回异常，请稍后重试 | `feishu_invalid_response` | 管理者检查飞书 API 返回结构、表字段名与类型；修复后复用原请求 ID | 服务不向浏览器透出飞书原始响应 |

`feishu_auth_failed` 仅表示租户令牌获取失败。`feishu_update_failed` 无法确认最终记录状态；重试时先按原请求 ID读取，若记录已完成则返回既有结果，否则继续使用已有关联记录。`feishu_invalid_response` 用于飞书返回内容不可解析或结构不符。

当前公开演示保持 `DEMO_MODE=false`，因此真实提交返回 `demo_disabled`，不会产生以上任一外部请求或写表。端到端失败恢复由本地确定性假服务验证，不是对线上 Dify/飞书可用性的实测声明。

## 当前限制

- 只处理仓库里的 10 份虚构样例，不提供自由文本问答或真实客户录入。
- 静态预览是固定示例，不因当前选择的样例重新生成。
- 暂无线上身份认证；启用实时入口前必须配置 Vercel WAF IP 限流：`/api/analyze` 和 `/api/retry` 每 IP 每 10 分钟最多 5 次。
- 应用采用短时 FastAPI 请求编排，不包含持久任务队列；部署前应确认外部工作流可以在时限内完成。
- 外部平台配额、价格和可用性由用户账号与供应商控制台决定。

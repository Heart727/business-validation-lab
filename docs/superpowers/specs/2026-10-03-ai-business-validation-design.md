# AI 经营分析与 7 天验证助手：设计说明

## 目标

交付一个面试官可匿名打开、能用虚构样例实际跑通的 AI 应用，展示从业务资料收集、飞书多维表格记录、AI 分析到 7 天验证行动计划的完整交付过程。新项目独立于 AI 销售助手。

## 备选方案与决策

1. **FastAPI + Dify Cloud Sandbox + 飞书多维表格（选择）**：Python 负责输入校验、流程协调和飞书读写；Dify 是唯一的 AI 工作流平台，负责调用 DeepSeek 并返回结构化分析。部署在 Vercel Hobby，不需要购买云服务器。Dify Sandbox 有免费配额，Vercel Python Runtime 当前为 Beta；平台限额和模型调用成本须在部署时复核。
2. **FastAPI + n8n Cloud + 飞书**：可视化编排能力更强，但官方云方案试用后需要订阅，不符合本项目尽量没有固定费用的要求。
3. **FastAPI + 自托管 n8n + 飞书**：流程可视化且不付 n8n 云订阅，但需要可长期运行的服务器、维护和公网入口；用户目前没有云服务器，因此不选。

选用方案 1。DeepSeek 通过 Dify 的模型供应商配置，调用费用由用户的 DeepSeek 账户承担；所有自动化平台只使用 Dify，不加入 n8n。

## 用户与范围

主要用户是面试官或项目负责人。访客无需登录，使用预置的虚构商家样例提交一次分析，并能看到结果卡片；操作者可在自己配置的飞书演示多维表格中查看同一记录。公开体验不接受真实客户姓名、电话、邮箱等个人信息。

包含：

- 中文、移动端友好的单页表单及结果卡片。
- 10 份固定、虚构的商家资料，用于公开演示与验收。
- FastAPI 校验、流程协调、飞书记录创建/更新及 Dify API 服务端代理。
- Dify Workflow 调用 DeepSeek，产出经营分析和严格 7 天行动清单。
- 飞书演示表格中的原始资料、分析结果、行动项、处理状态和请求 ID。
- 状态提示、失败恢复、幂等重试、测试、截图、README 和项目案例页。

不包含：真实客户资料接入、销售线索系统、登录/权限管理、自动定时执行 7 天任务、付款或商业化多租户功能。

## 架构与数据流

```text
公开样例页（10 份虚构资料）
  → Vercel 上的 FastAPI
  → 校验和公开入口限流
  → 飞书演示多维表格：创建“处理中”记录
  → Dify Workflow：调用 DeepSeek，生成 JSON 分析与 7 天行动
  → FastAPI 校验模型输出并更新原飞书记录
  → 页面显示结果卡片及飞书记录状态
```

FastAPI 是唯一的业务流程协调者。它先把输入写入飞书，再调用 Dify，成功后更新相同记录；Dify 不持有飞书凭据。网页只调用同源 FastAPI，不接触 Dify、飞书或 DeepSeek 密钥。飞书记录标记为 `DEMO`，并带稳定 `request_id`；重试时优先查找该 ID 并更新已有记录。飞书接口不提供跨步骤事务，设计不承诺并发重复请求下的数据库级唯一约束。

### 输入

每条固定样例包含：行业/业务类型、产品或服务、目标客户、当前经营问题、现有指标（可以为空）、预算范围、目标和时间限制。客户端只能选中预置样例 ID，后端从版本控制中的样例清单读取正式内容，不信任客户端自行提交的样例文字。

### AI 输出

Dify Workflow 返回 JSON：

- `executive_summary`：简洁经营摘要。
- `observations`：证据、推断与缺失信息分开写，不能把假设伪装成事实。
- `risks`：当前资料可能带来的限制或风险。
- `seven_day_actions`：恰好 7 项，每项包含日期序号、具体动作、要记录的指标、继续/调整/停止的判断条件。

如果用户没有提供可用指标，模型应指出需要先建立基线，不得虚构业绩数字或保证收益。FastAPI 使用 Pydantic 校验输出结构和 7 项行动数；不合格结果按模型输出失败处理，不写成成功状态。

## 组件边界

- `app/main.py`：FastAPI 路由、静态页服务、公开错误响应。
- `app/config.py`：读取和检查环境配置；不输出密钥。
- `app/schemas.py`：样例输入与分析 JSON 的 Pydantic 模型。
- `app/services/pipeline.py`：流程顺序、状态变化、重试和请求 ID。
- `app/services/feishu.py`：租户令牌获取、Bitable 记录创建、查询和更新。
- `app/services/dify.py`：Dify Workflow 调用、超时和响应解析。
- `data/scenarios.json`：10 份虚构场景，字段内容不得包含真实个人信息。
- `static/`：原生 HTML、CSS、JavaScript；前端只发送样例 ID并渲染 API 返回结果。
- `tests/`：配置、输入输出校验、失败分支、幂等行为和完整流程 mock 测试。
- `docs/`：部署说明、截图、案例页素材及失败记录。

## 错误处理与安全边界

流程状态固定为 `processing`、`completed`、`retryable_failed`。先成功创建飞书记录后若 Dify 超时、拒答或返回无效 JSON，该记录保留并标记 `retryable_failed`；页面不伪造分析内容。飞书创建或更新出错时显示稳定错误码和重试提示，不向访客泄露上游响应、令牌或密钥。重复重试查找并更新同一 `request_id` 的记录。

公开入口只接收 10 个固定样例 ID，拒绝任意自由文本。Vercel 部署配置一个 WAF 规则，针对分析 API 按来源 IP 固定窗口限制每 10 分钟最多 5 次；Dify 的月度触发/API 配额提供额外平台调用限制。该方案能降低常见脚本滥用与意外调用，不能保证抵御分布式攻击，也不能保证 DeepSeek 账户不会产生费用。部署前需在 DeepSeek 账户设置可用的消费告警/限额；演示记录只写独立的飞书演示表，禁止配置真实客户表。

密钥只通过部署平台环境变量或 Dify 的凭据配置管理：

- Vercel：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_TOKEN`、`FEISHU_TABLE_ID`、`DIFY_BASE_URL`、`DIFY_WORKFLOW_API_KEY`、`DEMO_MODE`。
- Dify：DeepSeek API Key、模型名与 Workflow 配置。
- 仓库仅含 `.env.example`，只列变量名称与无效示例值；禁止提交 `.env`、真实样例联系人或访问令牌。

Vercel Hobby 的 Python Runtime 目前为 Beta，函数最长运行 60 秒。外部请求必须设明确超时并留出函数响应余量；若模型调用超时，先保留飞书记录，再返回可重试状态。公开页面明确使用虚构样例，模型调用会消耗 DeepSeek 额度。

## 验收标准

1. Vercel 匿名窗口可以打开中文表单并使用移动端布局；不登录任何账号即可查看流程说明和结果。
2. 10 个虚构样例都能通过本地 mock 完整流程测试；配置测试服务后，10 个样例逐一走过实际飞书与 Dify 集成并保存结果。
3. 每条成功记录在飞书只有一条以 `request_id` 标识的演示记录，包含输入、摘要、分析、7 天动作和 `completed` 状态；重试更新现有记录。
4. 对至少 3 个失败场景记录输入、可见输出和恢复方法：无效样例 ID、Dify 超时/无效 JSON、飞书鉴权或写入失败。
5. 有密钥缺失时服务拒绝运行集成流程，浏览器和仓库均不暴露密钥。
6. 项目案例页含需求、流程图、4 张关键截图、代码/演示链接及作者负责范围；README 说明本地与线上配置、限制、运行和验证步骤。
7. 完成匿名浏览器验证、自动化测试、`git diff --check` 和无秘密扫描。真实 API 验收明确标注会调用 DeepSeek 并写入飞书演示表。

## 测试策略

- 单元测试：只允许的样例 ID、空/边界指标、模型 JSON 字段、正好 7 项行动、时间/预算格式、密钥缺失。
- 集成测试：使用 fake Feishu 与 fake Dify 验证先建记录、后调用 AI、再更新记录的顺序；注入超时、HTTP 错误、畸形 JSON 和重复请求，确认状态与记录可恢复。
- 真实服务验收：在用户专用的 Dify Workflow 和飞书演示表配置完成后，运行 10 份虚构样例；调用会消耗 DeepSeek 配额并写入飞书。
- 浏览器验收：匿名桌面/手机视口完成一条固定样例流程，验证空状态、处理中、成功与失败提示。

## 部署与费用

Vercel Hobby 托管 FastAPI 和静态页面，Dify Cloud Sandbox 运行唯一 AI Workflow，飞书多维表格保存演示结果。不购买云服务器。Dify/Vercel 的计划额度与 WAF 费率会变化，部署前复核官方页面；DeepSeek API 调用按账户计费，模型输出长度与调用次数需控制。超过平台免费额度或需要启用付费功能时，先暂停公开分析入口，不自动升级付费方案。

## 第五天交付物

- 可匿名打开的演示页面；若第三方服务暂不可用，页面明确显示服务状态并提供预置结果查看，不伪装成实时执行。
- GitHub 项目代码与可复现 README。
- 4 张项目截图：表单、处理中/状态、分析结果、飞书演示记录。
- 10 个虚构样例测试结果、3 个以上失败场景说明及恢复方式。
- 一页项目案例说明，包含业务问题、流程图、组件、验收证据与个人负责内容，可放在简历项目栏首位。
